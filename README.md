# directree.js

Create directory trees with files and content

[![Build](https://github.com/kdabir/directree.js/actions/workflows/build.yaml/badge.svg)](https://github.com/kdabir/directree.js/actions/workflows/build.yaml)

## Use cases

- **CLI scaffolding tools**: the file-writing engine behind a
  `create-*`-style generator. Describe the target project as one object;
  `directree()` writes it, skipping files that already exist unless told
  to `overwrite`.
- **Test fixtures**: set up a known directory structure before a test
  runs, without shelling out to `mkdir -p`/`touch` or hand-rolling `fs`
  boilerplate in every test file.
- **Snapshot testing a scaffolder**: round-trip through `read()` to
  assert a generator produced exactly the tree you expect, as a plain
  object comparison (`expect(read(dir)).toEqual(tree)`) instead of
  diffing files on disk one by one.

## Install

`npm install directree.js`

## Usage

```javascript
import directree, { json, md } from 'directree.js'

directree({
  'package.json': json({
    name: 'my-app',
    version: '0.1.0',
    type: 'module',
    scripts: { start: 'node src/index.js', test: 'vitest' },
  }),
  'README.md': md`
    # my-app

    Generated by create-my-app.
  `,
  '.gitignore': 'node_modules\ndist\n',
  'src': {
    'index.js': 'console.log("hello, world")\n',
  },
  'test': {
    'index.test.js': "import { it, expect } from 'vitest'\n\nit('works', () => expect(true).toBe(true))\n",
  },
}, 'my-app');
```

That's a small but complete scaffolder: a package.json built from a real
object (see `json`, below), a README written with a syntax-highlighted
template tag (see the tags section, below), plain strings for everything
else, and nested directories expressed as nested objects, all written into
a new `my-app` directory in one call.

Pass file tree representation as a simple json object to
`directree(tree, opts)`.

Keys are used as file/dir name. If the value is a string (or `null`,
treated as an empty file), a file will be created. If the value is an
object, a directory will be created.

`opts` can be a plain string, used as the root directory (defaults to
`"."` if omitted), or an options object:

```javascript
directree(tree, {
  root: 'out',        // defaults to "."
  overwrite: true,    // overwrite existing files instead of skipping them (default: false)
  dryRun: true,       // compute the write plan without touching disk (default: false)
});
```

`directree()` returns a `WritePlan` describing what happened (or, with
`dryRun`, what would happen), with paths relative to `process.cwd()`:

```javascript
{
  created: ['out/new.file', 'out/some-dir/nested.file'],
  skipped: ['out/existing.file'],  // already existed, overwrite was false
  dirs: ['out', 'out/some-dir'],
}
```

### `read(dir)`

The inverse of `directree()`: it reads a directory back into a `Tree` object.
Useful for snapshot testing a scaffolder built on top of `directree()`:

```javascript
import directree, { read } from 'directree.js'

directree({ 'a.txt': 'A', 'dir': { 'b.txt': 'B' } }, 'out')
read('out') // => { 'a.txt': 'A', 'dir': { 'b.txt': 'B' } }
```

`read()` recurses into every subdirectory and loads every file's content into
memory, so it's guarded against being pointed at something huge by
accident. `read()` is meant for scaffold/test-fixture-sized directories,
not general-purpose directory walking, so the defaults are deliberately
tiny: `maxDepth` (default 3), `maxFiles` (default 15), and `maxSize`
(default 10,240 bytes / 10 KB, total across all files) all throw a clear error the
moment they're exceeded, checked via a metadata-only pass before any file
content is actually read. Anything bigger has to opt in explicitly.
Binary files (detected the same way `git` does: a NUL byte in the first
few KB) are excluded from the result entirely rather than inlined as garbled text,
and don't count toward the limits either. Pass an `ignore` predicate to
exclude a subtree (like `node_modules`) up front instead of relying on the
caps:

```javascript
read('.', {
  ignore: (name) => name === 'node_modules' || name === '.git',
  maxFiles: 200, // override a default if you really mean it
})
```

### Syntax-highlighting template tags

`html`, `css`, `sql`, `yaml`, `md`, `xml`, `json`, `csv`, `toml`, `text`,
`makefile`, `tsx`, `ts`, `jsx`, and `js` are exported as tagged-template
functions. Editors that recognize tagged-template conventions (WebStorm's
built-in language injection, VS Code extensions matching on the tag
identifier) will syntax-highlight the content inside the backticks, which
is their main purpose.

They also dedent: write the content indented to match the surrounding
source (the natural way to write it), and the shared left margin is
stripped from the result, while relative indentation between lines is kept.
A template with nothing to strip (the common single-line case) is
unaffected.

```javascript
import directree, { html, css } from 'directree.js'

directree({
  'index.html': html`
    <!doctype html>
    <h1>${title}</h1>
  `,
  'style.css': css`body { margin: 0; }`,
}, 'out');
// index.html's content on disk: "<!doctype html>\n<h1>...</h1>"
```

Entirely opt-in: plain strings work exactly as before. Note the
highlighting is keyed to the literal tag name at the call site, so a
runtime-built tag (e.g. from a factory function) won't get picked up by
these editor integrations even though it'd behave identically at runtime.

`raw` is also exported: it interpolates the same way but skips dedent, for
the rare case where source-level whitespace needs to be preserved exactly.

Two tags do a bit more than dedent:

- **`makefile`** converts each recipe line's indentation to a real tab:
  `make` requires one before every recipe line, no exceptions. Deeper
  indentation within a recipe is kept as spaces after the tab, so nested
  shell structure still reads clearly. One gotcha: write `\\` rather than
  `\` for Make's own line-continuation, since a lone `\` before the
  template literal's newline is consumed by JS itself before the tag ever
  sees it.
- **`json`** also accepts a plain value instead of a template literal:
  `json({ name: 'x' })` serializes it with `JSON.stringify(value, null, 2)`.
  A real object literal beats hand-typing JSON text for anything beyond
  the trivial case, and it still works as a tagged template when called
  with backticks.

## Known limitations

Keys that look like array indices (e.g. `"1"`, `"2"`) are reordered by the
JS engine ahead of other string keys, per the
[spec-defined object key ordering](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/keys#description)
for integer-like keys. This means files/dirs named e.g. `"1"` or `"2"` may
be created before other entries regardless of where they appear in the
source object. This is a JS language behavior, not something directree.js
can override without changing the input shape (e.g. to an array of
`[name, value]` entries). There are no plans to do that right now.
